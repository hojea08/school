# 오류 정정 부호 — 패리티와 해밍 코드

> **한 줄 요약**
> 통신·저장 과정에서 비트가 뒤집히는 것을 막을 수는 없으니,
> **의도적으로 여분의 비트(중복)를 덧붙여** 오류를 **찾아내고(검출) 고칩니다(정정).**
> 핵심 저울질은 **중복을 늘릴수록 안전해지지만 효율은 떨어진다**는 것입니다.

---

## 1. 기본 개념

| 용어 | 뜻 |
|---|---|
| **부호어(codeword)** | 실제로 전송하는 비트열 (데이터 비트 + 검사 비트) |
| **검출(detection)** | 오류가 **있다는 사실**을 알아냄 → 재전송 요청 |
| **정정(correction)** | 오류의 **위치를 찾아 스스로 고침** → 재전송 불필요 |
| **중복(redundancy)** | 정보를 담지 않는 여분의 비트 |
| **부호율(code rate)** | 데이터 비트 / 전체 비트. 높을수록 효율적, 낮을수록 안전 |

> **왜 정정까지 하나?**
> 재전송이 불가능하거나 비싼 상황(위성 통신, 저장 매체, 실시간 방송)에서는
> **받은 쪽에서 스스로 고쳐야** 합니다. 이를 **순방향 오류 정정(FEC)** 이라 합니다.

---

## 2. 패리티 비트 — 가장 단순한 방법

> 데이터의 **1의 개수**가 짝수(또는 홀수)가 되도록 **검사 비트 1개**를 덧붙인다.

**짝수 패리티 예시**

| 데이터 | 1의 개수 | 패리티 비트 | 전송 |
|---|---|---|---|
| 1011 | 3 (홀수) | **1** | 10111 |
| 1010 | 2 (짝수) | **0** | 10100 |

**수신 측:** 받은 비트열의 1의 개수가 **짝수가 아니면 오류**입니다.

### 패리티의 능력과 한계 ★

| 가능 | 불가능 |
|---|---|
| **1비트 오류 검출** | **오류 위치 파악 → 정정 불가** |
| 홀수 개 오류 검출 | **2비트(짝수 개) 오류는 검출 불가** ★ |

> **왜 2비트 오류를 못 잡나?** 두 비트가 뒤집히면 1의 개수의 **홀짝이 원래대로 돌아옵니다.**
> 그래서 패리티 검사를 통과해버립니다. 이것이 패리티의 결정적 한계입니다.

**정정하려면 무엇이 필요한가?**
검사 비트가 **1개**면 "오류가 있다/없다"는 1비트 정보만 얻습니다.
**위치**를 알려면 더 많은 검사 비트가 필요합니다. → 해밍 코드의 출발점입니다.

---

## 3. 해밍 거리 — 부호의 성능을 재는 자

> **해밍 거리**: 같은 길이의 두 비트열에서 **서로 다른 자리의 개수**.

예) 1011 과 1001 → 3번째 자리만 다름 → 해밍 거리 **1**

> **최소 해밍 거리 d**: 그 부호에 속한 **모든 부호어 쌍** 사이 거리 중 **가장 작은 값**.

### 성능 공식 ★

| 능력 | 조건 |
|---|---|
| **t비트 검출** | d ≥ t + 1 |
| **t비트 정정** | d ≥ 2t + 1 |

**직관적으로 이해하기**

부호어들을 공간 속의 점이라고 생각해 보세요.

- **검출**: 오류가 생겨 다른 **부호어와 겹치지만 않으면** "이상하다"는 걸 압니다
  → 거리가 t+1이면 t비트 오류로는 다른 부호어에 닿지 못합니다
- **정정**: 오류가 생긴 지점에서 **가장 가까운 부호어**로 되돌립니다
  → 그러려면 각 부호어 주위에 반지름 t의 **겹치지 않는 영역**이 필요합니다
  → 부호어 사이 거리가 최소 **2t+1**이어야 합니다

| 최소 거리 d | 검출 | 정정 |
|---|---|---|
| 2 | 1비트 | 불가 (패리티) |
| **3** | 2비트 | **1비트** (해밍 코드) |
| **4** | 3비트 | 1비트 정정 + **2비트 검출** (확장 해밍, SECDED) |

## 4. 해밍 코드 (7,4)

> 데이터 **4비트** + 패리티 **3비트** = 전송 **7비트**. 부호율 4/7.

### 배치

패리티 비트를 **2의 거듭제곱 위치**(1, 2, 4번)에 놓고, 나머지에 데이터를 넣습니다.

| 위치 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| 역할 | **P1** | **P2** | D1 | **P4** | D2 | D3 | D4 |

### 각 패리티가 담당하는 자리

> **규칙:** 위치 번호를 **2진수**로 썼을 때, 해당 자릿수가 1인 위치들을 담당합니다.

| 패리티 | 담당 위치 | 근거 (2진수의 어느 자리가 1인가) |
|---|---|---|
| **P1** | 1, 3, 5, 7 | 1의 자리 = 1 (001, 011, 101, 111) |
| **P2** | 2, 3, 6, 7 | 2의 자리 = 1 (010, 011, 110, 111) |
| **P4** | 4, 5, 6, 7 | 4의 자리 = 1 (100, 101, 110, 111) |

각 패리티는 자기가 담당하는 자리들의 1의 개수가 **짝수가 되도록** 정해집니다.

### 정정 원리 — 신드롬 ★★★

수신 측에서 세 검사를 다시 수행하고, **실패한 것은 1, 통과한 것은 0**으로 적습니다.

> 그 결과(**P4 P2 P1** 순)를 **2진수로 읽으면 곧바로 오류가 난 위치**입니다.

| 검사 결과 (P4,P2,P1) | 2진수 | 오류 위치 |
|---|---|---|
| 0,0,0 | 000 | **오류 없음** |
| 0,0,1 | 001 | 1번 비트 |
| 0,1,1 | 011 | **3번 비트** |
| 1,0,1 | 101 | 5번 비트 |
| 1,1,1 | 111 | 7번 비트 |

**왜 이렇게 되나?**
각 위치는 **자기를 담당하는 패리티들의 조합이 서로 다릅니다.**
3번 위치는 P1과 P2가 담당하고 P4는 담당하지 않으므로,
3번이 뒤집히면 **P1, P2만 실패**합니다 → 011 → 3번. **위치가 유일하게 특정됩니다.**

### 확장 해밍 (8,4) — SECDED

전체에 패리티 1개를 더 붙여 최소 거리를 **4**로 만듭니다.

| 상황 | 판별 |
|---|---|
| 신드롬 0, 전체 패리티 정상 | 오류 없음 |
| 신드롬 ≠ 0, 전체 패리티 이상 | **1비트 오류 → 정정** |
| 신드롬 ≠ 0, 전체 패리티 **정상** | **2비트 오류 → 검출만** (정정 불가) |

> **SECDED** = Single Error Correction, Double Error Detection.
> 컴퓨터 메모리(ECC RAM)에 실제로 쓰입니다.

## 5. 다른 부호들 (지문에 함께 나올 수 있음)

| 부호 | 특징 |
|---|---|
| **CRC** | 다항식 나눗셈의 나머지를 검사 비트로. **검출 전용**이지만 **버스트 오류 검출에 강함**. 네트워크 프레임에 널리 사용 |
| **리드-솔로몬** | **바이트(심볼) 단위**로 정정. **연속된 오류(버스트)** 에 강함. CD/DVD, QR코드 |
| **인터리빙** | 데이터를 **섞어서** 전송. 수신 후 되돌리면 **뭉쳐 있던 오류가 흩어져** 1비트 정정 부호로도 처리 가능 ★ |

> **인터리빙의 발상이 재미있습니다.** 부호 자체를 강화하는 게 아니라,
> **오류의 분포를 바꿔** 기존 부호가 감당할 수 있게 만듭니다.

## 6. 근본적 저울질

```
 중복 ↑  →  오류 정정 능력 ↑ , 부호율(효율) ↓
 중복 ↓  →  전송 효율 ↑     , 오류에 취약 ↑
```

| 상황 | 선택 |
|---|---|
| 채널 잡음이 심하고 재전송 불가 (위성, 심우주 통신) | 중복 많이 → 강한 정정 |
| 채널이 깨끗하고 재전송 쉬움 (근거리 유선) | 검출만 + 재전송 |

## 7. 지문은 이렇게 전개된다

```
① 통신 중 오류는 피할 수 없다 → 중복의 필요성
        ↓
② 패리티 비트 — 가장 단순한 검출
        ↓
③ 패리티의 한계 (위치 모름, 2비트 오류 못 잡음)
        ↓
④ 해밍 거리 — 성능을 재는 개념
        ↓
⑤ 해밍 코드의 구조와 신드롬에 의한 위치 특정
        ↓
⑥ 확장 해밍 / 버스트 오류 대응(인터리빙, RS 부호)
        ↓
⑦ 효율과 신뢰성의 상충
```

## 8. ⚠️ 선지 함정 포인트

1. **"패리티 비트로 오류를 정정할 수 있다" → 틀림.**
   **검출만** 가능합니다. 위치를 모르므로 고칠 수 없습니다.

2. **"패리티 비트는 모든 오류를 검출한다" → 틀림.**
   **짝수 개(2비트 등)의 오류는 검출하지 못합니다.** 홀짝이 원래대로 돌아오기 때문입니다.

3. **정정과 검출 공식을 바꾸지 마세요.**
   **검출: d ≥ t+1 / 정정: d ≥ 2t+1.**
   정정이 검출보다 **더 큰 거리**를 요구합니다 (고치려면 더 여유가 필요하니까요).

4. **"최소 해밍 거리가 3이면 2비트를 정정할 수 있다" → 틀림.**
   d=3이면 **1비트 정정 / 2비트 검출**입니다.

5. **"해밍 코드는 몇 비트 오류든 정정한다" → 틀림.**
   기본 해밍 코드는 **1비트 정정**만 가능합니다.

6. **"오류 정정 부호를 쓰면 전송 효율이 높아진다" → 틀림.**
   **중복 비트가 늘어나므로 효율(부호율)은 떨어집니다.**
   대신 재전송이 줄어드는 이득이 있는 것이죠. 지문이 어느 쪽을 말하는지 보세요.

7. **"인터리빙은 오류의 개수를 줄인다" → 틀림.**
   개수는 그대로이고 **분포를 흩뜨릴** 뿐입니다.
   뭉쳐 있던 오류가 흩어져 **기존 부호로 감당 가능해지는** 것입니다.

8. **"CRC는 오류를 정정한다" → 틀림.**
   CRC는 **검출 전용**입니다.

9. **해밍 코드에서 패리티 비트의 위치를 헷갈리지 마세요.**
   **1, 2, 4, 8… (2의 거듭제곱)** 자리입니다. 이 배치 덕분에 신드롬이 곧 위치가 됩니다.

## 9. 확인 문제

**Q1.** 짝수 패리티를 쓰는 시스템에서 `1011010`을 받았다. 오류가 있는가?

<details><summary>정답</summary>

1의 개수 = 4개(짝수) → **패리티 검사 통과**, 오류가 검출되지 않습니다.
단, **2비트 오류가 났다면 검사를 통과할 수 있으므로** "오류가 절대 없다"고는 할 수 없습니다.
패리티는 **"오류가 없다"를 보장하지 못합니다.**
</details>

**Q2.** 어떤 부호의 최소 해밍 거리가 5이다. 몇 비트까지 검출·정정할 수 있는가?

<details><summary>정답</summary>

- **검출**: d ≥ t+1 → t ≤ 4 → **4비트까지 검출**
- **정정**: d ≥ 2t+1 → t ≤ 2 → **2비트까지 정정**
</details>

**Q3.** 해밍 코드 (7,4)에서 P1과 P2 검사는 실패하고 P4 검사는 통과했다. 오류 위치는?

<details><summary>정답</summary>

(P4, P2, P1) = (0, 1, 1) → 2진수 **011 = 3** → **3번 비트**에 오류.
3번 위치는 P1·P2가 담당하고 P4는 담당하지 않으므로 정확히 이 패턴이 나옵니다.
</details>

**Q4.** "인터리빙을 사용하면 연속된 여러 비트가 손상되어도 1비트 정정 부호로 복구할 수 있다."

<details><summary>정답</summary>

**맞음(O).** 전송 전에 데이터 순서를 **섞어** 보내고 수신 후 되돌리면,
전송 중 **뭉쳐서 발생한 버스트 오류**가 여러 블록에 **하나씩 흩어집니다.**
따라서 각 블록은 1비트 오류만 갖게 되어 1비트 정정 부호로 복구할 수 있습니다.
</details>
